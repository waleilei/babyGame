# 提示词目录：520 条步骤图提示词的唯一来源

Status: ready-for-agent
Source: 2026-10-20 设计评审（Q1-Q6 逐项确认；Q7-Q14 按推荐）
Related: ADR-0002「提示词目录归 babyGame 所有」；`GLOSSARY.md`（步骤图 / 提示词）；`../docs/illustration-style.md` 与 `prompts/image-prompt-catalog.md`（书稿项目）

## Problem Statement

520 条提示词只存在于书稿项目的一份 markdown 里，而图片、图片编号与「游戏 → 四张步骤图」的对应关系只存在于 babyGame。两者靠人脑对齐：书稿项目一旦不再维护，这份唯一副本就没有着落。

内容本身也难维护。449 条是旧「吉卜力式」单句模板，71 条是 2026-10 修复批次的四层模板，同一批图混着两种写法；每条都从头写到尾，想改「客厅」的场景词，得手改几十条；想改负面清单，520 条全要动。没有结构化字段，就没有「改一处、整批生效」的可能。

校验也不存在。少一条、多一条、出现禁画项（学步车、脖圈、床围、趴睡、手机哄娃、整粒坚果、蜂蜜）、宝宝月龄与游戏对不上，全都只能靠人眼在 20 万字节里找。重绘时拿到一条缺字段的提示词，问题要到出图之后才发现。

## Solution

把这份目录复制进 babyGame 并成为唯一来源，原表冻结归档不再改动；把 520 条提示词按「共享层 + 格层」重写为可组合的结构化记录：风格、人物、镜头、场景、负面各有一份字典，每张步骤图只写自己的镜头、场景、动作与道具，最终文案由固定模板拼出。

目录按游戏章拆分，与 `data/chapters` 同构，改一章只看一个文件；每格一行一个字段，diff 干净。`npm run prompt 006-3` 打印拼好的最终文案，`npm run check` 校验键与图片双向一致、字典引用有效、禁画项、月龄一致。不产出运行期 JSON，不进网页，不占运行期 JS 预算。

449 条旧文案按四层模板重写，重写时以插画脚本的画面、手部、表情与游戏步骤为依据；每格带 `draft` / `reviewed` 状态，让「还剩多少条没人看过」变成可统计的事实。

## User Stories

1. 作为内容维护者，我希望 520 条提示词存放在 babyGame 仓库里，以便图片与文案不再跨仓库对齐。
2. 作为内容维护者，我希望原总表冻结归档、只读保留，以便日后复核「重写时改了什么」。
3. 作为内容维护者，我希望每条提示词由共享层与格层拼成，以便改一处风格词能整批生效。
4. 作为内容维护者，我希望风格前缀只存在一份，以便 520 条不会出现两种开头。
5. 作为内容维护者，我希望负面清单只存在一份，以便新增禁画项时不用逐条改。
6. 作为内容维护者，我希望人物设定按宝宝月龄自动取用，以便同一游戏的四个步骤图写法一致。
7. 作为内容维护者，我希望镜头有固定词表（平视中景 / 俯拍 / 侧低角 / 特写 / 全景），以便不再出现 32 种自由写法。
8. 作为内容维护者，我希望场景收敛为 7 类加一个兜底，以便「客厅」的光线与道具只维护一份。
9. 作为内容维护者，我希望每个场景有全景版与特写版两段文案，以便特写镜头不被背景元素撑长。
10. 作为内容维护者，我希望 `床/地垫` 这类复合场地默认取第一项为主场景，同时保留完整场地数组，以便不丢信息。
11. 作为内容维护者，我希望某张步骤图的场景与场地不符时能单独覆盖，以便默认值不成为枷锁。
12. 作为内容维护者，我希望目录按游戏章拆成 14 个文件，以便改第 8 章只打开第 8 章。
13. 作为内容维护者，我希望每格一行一个字段，以便 diff 只显示改动的那一行。
14. 作为内容维护者，我希望拼接规则由模板统一负责句读，以便格层只写内容、不操心标点。
15. 作为内容维护者，我希望格层字段留空有明确口径（道具可空、其余必填），以便校验能区分「漏写」与「确实没有」。
16. 作为内容维护者，我希望每格带 `draft` / `reviewed` 状态，以便知道哪些还没人看过。
17. 作为内容维护者，我希望先定稿第 5 章作为校准样本，以便后续章节照同一把尺子推进。
18. 作为内容维护者，我希望重写时优先采用插画脚本的画面与手部，以便动作描述有据可依。
19. 作为内容维护者，我希望没有插画脚本的 80 格改用游戏步骤，以便每一格都有可靠来源。
20. 作为内容维护者，我希望道具从游戏材料字段取用，以便提示词与玩法说明不打架。
21. 作为内容维护者，我希望插画脚本里的「标签」与「安全插图」角标不得进入画面描述，以便提示词不诱导模型画出文字。
22. 作为内容维护者，我希望禁画项在拼接结果里被自动检出，以便学步车、脖圈、床围、趴睡、手机哄娃、整粒坚果、蜂蜜不会漏进画面。
23. 作为内容维护者，我希望宝宝月龄与所属游戏一致，以便 0-3 月的游戏不会出现会跑的宝宝。
24. 作为内容维护者，我希望提示词键与图片文件双向一致，以便既不缺条目也不留孤儿。
25. 作为内容维护者，我希望每张步骤图都有对应图片与所属游戏，以便断链在提交前暴露。
26. 作为内容维护者，我希望文件章号与章节数据一致，以便第 8 章的文件里不会混进第 9 章的游戏。
27. 作为内容维护者，我希望超长文案只报警告，以便长度不变成绕过门禁的理由。
28. 作为内容维护者，我希望同一游戏四格动作高度重复时收到警告，以便发现「四格同图」。
29. 作为内容维护者，我希望场景与场地主项不一致时收到警告，以便复核默认映射的偏差。
30. 作为开发者，我希望用一条命令打印任意一步骤图的最终文案，以便回答「这张图当初是怎么描述的」。
31. 作为开发者，我希望打印结果可以直接复制去生成，以便不用手工拼接。
32. 作为开发者，我希望校验失败时看到步骤图编号与文件位置，以便直接跳到出问题的那一行。
33. 作为开发者，我希望校验通过退出码为 0、失败为 1，以便接进现有门禁。
34. 作为开发者，我希望提示词不产出 `data/` 下的 JSON，以便不出现第二份真相。
35. 作为开发者，我希望提示词相关代码不进入运行期模块，以便运行期 JS 预算不变。
36. 作为开发者，我希望提示词目录不依赖书稿仓库的路径，以便 CI 与门禁可独立运行。
37. 作为开发者，我希望解析器只认一种块格式并在遇到未知写法时报错，以便格式漂移立刻可见。
38. 作为开发者，我希望组合函数是纯函数，以便用合成夹具测边界而不碰真实文件。
39. 作为复审者，我希望一次看到某游戏的四条完整文案，以便判断四格是否真的不同。
40. 作为复审者，我希望看到 `draft` 与 `reviewed` 的统计，以便知道这批还有多少没复核。
41. 作为复审者，我希望原表与新版能对照，以便判断重写是否丢掉了原有画面信息。
42. 作为书稿项目的生成流水线，我希望提示词改从 babyGame 读取，以便不再维护第二份目录。
43. 作为后来加入的开发者，我希望词汇表里写明「步骤图」与「提示词」，以便不再和书稿的「格」混用。
44. 作为后来加入的开发者，我希望 ADR 写明目录为何归 babyGame，以便不会有人把它搬回去。

## Implementation Decisions

### 1. 归属与目录契约

提示词目录归 babyGame 所有，书稿项目不再保留（ADR-0002）。目录形状：

```
prompts/
├── README.md                 改法、校验方式、拼接顺序
├── presets/
│   ├── style.md              风格层（唯一一份）
│   ├── negative.md           负面层（唯一一份，四类禁画项）
│   ├── character.md          人物层（妈妈固定 + 宝宝按月龄）
│   ├── camera.md             镜头词表（5 个 id + 自由写法映射）
│   └── scene.md              场景字典（7 类 + 兜底，每类 full / brief 两段）
├── ch05.md … ch18.md         格层，一章一文件，与游戏章同构
└── archive/
    └── image-prompt-catalog.md   原总表，冻结只读，不再修改
```

只有游戏章（第 5-18 章）有步骤图，故只有这 14 个文件。章首页与封面虽然在原表里有 9 条提示词，但 `assets/` 中无对应图片，不迁入。

### 2. 分层模型与拼接顺序

一条提示词由七层按固定顺序拼成，顺序不可由格层覆盖：

```
[风格层] + [人物层] + [镜头层] + 「，」 + [场景层] + 「。」 + [动作层] + 「。」 + [道具层?] + [负面层]
```

- 风格层：透明水彩绘本风、媒介与笔触、画幅 3:2 横构图、无文字无标签无边框。取自风格规范第十二节固定前缀，唯一一份。
- 人物层：妈妈为固定设定；宝宝按所属游戏的月龄填一句，月龄文案取自游戏数据原文（如 `0-3月`），不做二次换算。
- 镜头层与场景层：写 id，不写文本；文本由字典提供。镜头与场景之间用逗号连接，场景层结尾补句号。
- 动作层：只写这一格的画面，不含镜头、场景与标点结尾。
- 道具层：取自游戏材料字段；材料为「无」时整层省略，不写「道具：无」。
- 负面层：四类（画面 / 风格 / 结构 / 内容）合为一句，以「避免：」开头。
- 句读由模板统一补，格层字段不带句末句号。这是校验项，不是风格建议。

### 3. 预设字典

- **镜头**：平视中景（默认）、俯拍、侧低角、特写、全景。插画脚本里的 32 种自由写法由一份显式映射表归一；映射表里没有的写法直接报错，逼出新决定而不是静默兜底。
- **场景**：客厅 / 卧室 / 餐椅餐桌 / 厨房 / 浴室 / 户外 / 门厅，外加「室内通用」兜底。每个场景保留风格规范里的主色、关键元素与光线，并各写 `full`（全景、中景用）与 `brief`（特写、手部特写用）两段文案。
- **场景归属**：游戏的场地字段有 34 个取值，其中 47 个游戏是复合值（`床/地垫`、`餐椅/地垫` 等）。复合值取第一项为主场景，完整取值保留为数组；格层可逐条覆盖主场景。
- **人物**：妈妈固定；宝宝月龄词来自游戏数据。不做头身比、服装等自由发挥。
- **负面**：四类禁画项固定为一份；格层不写负面。

### 4. 格层文件格式

每格一个小节，字段一行，全角冒号：

```md
### 006-3　蹬腿自行车｜步骤图 3

- **镜头**：overhead
- **场景**：living-room
- **月龄**：0-3月
- **动作**：两腿交替，像蹬车；双手随节奏轻推；宝宝笑
- **道具**：无
- **状态**：reviewed
```

- 解析器只认 `### 编号　游戏名｜步骤图 N` 这一种标题、`- **键**：值` 这一种字段行，以及章节标题、引用说明与分隔线；其余内容一律报错，避免格式悄悄漂移。
- 字段固定为镜头、场景、月龄、动作、道具、状态六项；道具可省略或写「无」，其余必填。
- `月龄` 冗余存一份，让提示词脱离游戏数据也能复现；校验时与游戏数据比对，不一致即报错。
- `状态` 只有 `draft` 与 `reviewed` 两个值。

### 5. 重写策略

449 条旧文案按四层模板重写，不是搬运。素材优先级：

1. 插画脚本的「画面」→ 动作主句，「手部位置」→ 手部子句，「表情」→ 表情子句，「视角」→ 镜头（440 格可用）。
2. 无脚本的 80 格，用所属游戏的对应步骤作为动作主句（130 个游戏各 4 步，与四张步骤图一一对应）。
3. 游戏材料 → 道具；游戏场地 → 场景；游戏月龄 → 人物。
4. 风格规范 → 风格层、场景层、负面层。

插画脚本里的「标签」与「安全插图」角标是排版用文字，不得进入画面描述；画面内一切文字由负面层统一排除。

改写时参考所属游戏的玩法、步骤与材料字段，保证提示词描述的画面与该游戏实际在做的动作一致；安全提示只进负面层，不写进画面。

### 6. 评审状态

初版全部产出标 `draft`；先人工定稿第 5 章作为校准样本，其余章节逐章把 `draft` 改为 `reviewed`。`draft` 不阻断门禁，但校验输出统计「520 条中 draft N 条」，让未复核量始终可见。

### 7. 命令行契约

- `npm run prompt <编号>`：打印该步骤图的最终文案，末尾附所属游戏、月龄、状态；编号非法时退出码 1。
- `npm run prompt <游戏编号>`：打印该游戏四条文案，供复审一次看全。
- `npm run check`：在现有校验链后追加提示词校验，任一错误即非零退出。
- 不提供写盘、格式化或改写命令；文件由人编辑。

### 8. 校验口径

**错误**（阻断）：

- 提示词键与 `assets/` 中的步骤图双向一致：不缺失、不孤儿。
- 每格四个必填字段齐全，状态值合法，键与所属游戏、章节一致。
- 镜头与场景 id 在字典内；动作层不含句末句号、不含「标签」「安全插图」字样。
- 拼接结果出现禁画项（学步车、脖圈、床围、趴睡、手机哄娃、整粒坚果、蜂蜜）。
- 人物层月龄与所属游戏的月龄不一致。

**警告**（只打印）：

- 拼接结果超过 380 字（模板本身的固定开销已近 300 字，320 会让全部条目报警）。
- 同一游戏的四个动作层完全相同或高度重复。
- 格层场景不在场地允许的集合内：复合场地的每一段都算允许，全部不匹配才警告，默认取第一项。
- 某游戏的步骤图不足或超过 4 张。
- 提示词道具为空，但游戏材料不是「无」。

### 9. 运行期与体积

提示词不进运行期：不新增 `src/` 模块、不产出 `data/` JSON、不影响首屏请求数、不影响运行期 JS 预算。解析与组合逻辑放在构建期工具中，由校验脚本与命令行共同调用。

### 10. 文档更新

- `AGENTS.md` 的文档地图补提示词目录入口。
- 架构文档的目录结构补 `prompts/`，并注明它不进入运行期。
- 本次新增 ADR-0002；词汇表已收录「步骤图」与「提示词」。
- 原总表迁入后，书稿项目的生成流水线改读 babyGame 的产物；该改动不在本仓范围内，仅记录为前置条件。

## Testing Decisions

好的测试只验证外部可观察行为：给定一段目录文本与一份预设，断言解析结果、拼接文案、校验错误与统计数字；不测私有函数、不测 markdown 排版细节、不测命令行输出颜色。

**本次只新增一处缝隙，放在最高层**：构建期的提示词目录模块，公开「解析 / 组合 / 校验」三个纯函数，命令行与校验脚本都是它的薄壳。先例是现有数据管线测试直接引入构建期提取器——同一个模式，不新增测试框架。

这一点需要你确认：**不再为解析器、组合器、校验器分别开缝**，而是让三者共用一个模块边界；若这个缝隙与你的预期不符，先改本节再实现。

测试内容：

1. **真实目录**：520 条、键与图片双向一致、字典引用全部有效、禁画项为零、月龄全部对齐、`draft` / `reviewed` 统计可读。
2. **合成夹具**：缺字段、未知镜头、未知场景、重复键、错误标题、动作带句号、道具为空、特写取 `brief` 场景、复合场地取首项、格层覆盖场景。
3. **组合确定性**：同一输入重复组合结果逐字相同；层与层之间只有一个逗号或句号。
4. **错误信息**：每条错误都带步骤图编号，能定位到文件与字段。

不测：markdown 排版是否好看、命令行参数解析的细枝末节、文件写盘（本功能不写盘）。

## Out of Scope

- 网页内展示提示词（已确认不需要展示，不新增入口、不改弹层、不改大图查看器）。
- 网页内编辑、复制按钮、任何 UI 变更。
- 产出 `data/prompts.json` 或按章 JSON 产物。
- 章首页主视觉与封面的 9 条提示词。
- 按提示词重新生成或重绘 520 张图。
- 修改插画风格规范本身；风格规范仍以书稿项目文档为准，迁入时只摘取风格层所需的片段。
- 把提示词加入搜索、目录或任何运行期索引。
- 迁移报告的长期维护（一次性产物，出完即归档）。
