# babyGame v0.1 — 按章浏览的亲子游戏库

Status: ready-for-agent
Source: 2026-10-20 设计评审（两轮）+ 架构方案 v0.2

## Problem Statement

想陪 0-3 岁孩子玩的家长手里有一本 130 个游戏的纸质书，但临到要玩的时候查起来很慢：不知道当前月龄适合什么，翻目录、找页码、记住上一个游戏都费劲；出门在外只有手机时更没法用。

内容本身已经存在，但是 Markdown 稿件，既不能在手机上翻阅，也不能按“月龄/场景”快速定位，更没法把某个游戏直接发给家人。

## Solution

把书做成一个按章浏览的网页：打开先看到目录，按“篇”分组列出 14 个游戏章；点进一章，只加载这一章的内容；章内以卡片浏览游戏，点开看完整的 8 个模块和步骤图；顶部始终可以回目录、翻上一章/下一章；目录页可以按游戏名搜索并直达。每个游戏有独立链接，可分享、可刷新、可后退。

手机上单列、桌面上三列；一次只在页面上呈现一章，翻章不整页刷新。

## User Stories

1. 作为家长，我希望打开首页先看到目录，以便不等待游戏数据就能判断这本书里有什么。
2. 作为家长，我希望目录按“篇”分组（分月龄游戏图鉴、把游戏放进生活），以便按书的逻辑而不是一串编号找内容。
3. 作为家长，我希望目录每章显示章号、标题、月龄段和游戏数，以便快速判断这章是否适合我孩子。
4. 作为家长，我希望点一下目录里的章节就进入该章，以便不用先滚动或翻页。
5. 作为家长，我希望进入章节时只加载这一章，以便在移动网络下不浪费流量。
6. 作为家长，我希望章节开头能看到“发展地图/场景说明”，以便先了解这个阶段能期待什么。
7. 作为家长，我希望卡片上直接看到主图、编号、名称、月龄、能力和时长，以便一眼筛掉不合适的游戏。
8. 作为家长，我希望点开卡片看到完整的“玩、步骤、观察、进阶、降阶、安全、问”，以便照着做而不用回翻书。
9. 作为家长，我希望弹层里能看到 4 张步骤分解图，以便不识字或看不懂文字时也能照做。
10. 作为家长，我希望关闭弹层后回到刚才那张卡片的位置，以便继续浏览而不是重新找。
11. 作为家长，我希望在章节顶部和底部都能翻上一章/下一章，以便读完不用滚回顶部。
12. 作为家长，我希望从第 12 章能直接翻到第 13 章，以便从“月龄篇”自然过渡到“生活场景篇”。
13. 作为家长，我希望第 5 章的“上一章”和第 18 章的“下一章”是禁用状态，以便知道已经到边界。
14. 作为家长，我希望章节页始终有一个“目录”按钮，以便一次点击回到目录。
15. 作为家长，我希望把某个游戏的链接发给家人后，对方打开就能看到该游戏，以便直接交接玩法。
16. 作为家长，我希望刷新一个游戏深链后仍停在同一个游戏，以便链接稳定可靠。
17. 作为家长，我希望按浏览器后退能先关闭游戏弹层、再回到目录，以便符合直觉。
18. 作为家长，我希望在目录页按游戏名搜索，以便记得名字但忘了章节时也能找到。
19. 作为家长，我希望搜索结果标出章号、月龄和能力，以便点开前确认是不是要找的那个。
20. 作为家长，我希望搜索没有结果时看到明确提示和清除按钮，以便知道不是页面坏了。
21. 作为家长，我希望打开一个不存在的章节链接时被带回目录并看到提示，以便不卡在空白页。
22. 作为家长，我希望在 360px 宽的手机上单列浏览且没有横向滚动，以便单手操作。
23. 作为家长，我希望平板上双列、桌面上三列，以便大屏不浪费空间。
24. 作为家长，我希望手机上游戏弹层是全屏的，以便内容不被裁切。
25. 作为家长，我希望在桌面用左右方向键切章，以便连续翻阅。
26. 作为家长，我希望用 Tab 能到达所有卡片和按钮、用 Esc 能关闭弹层，以便不依赖鼠标。
27. 作为使用读屏的家长，我希望切章时听到新章标题、搜索时听到结果数量，以便知道页面变了。
28. 作为家长，我希望切章后页面回到顶部且焦点在章标题，以便从新章开头开始读。
29. 作为家长，我希望翻到下一章时几乎立刻出现，以便连续阅读不被打断。
30. 作为家长，我希望章节加载时看到骨架屏，以便知道正在加载而不是空白。
31. 作为家长，我希望加载失败时看到失败原因和“重试”，以便网络恢复后不用重新进目录。
32. 作为家长，我希望插画加载失败时看到同尺寸占位而不是塌陷的卡片，以便继续浏览。
33. 作为内容维护者，我希望用一条命令把最新稿件重新生成网页数据，以便改稿后不用手工同步。
34. 作为内容维护者，我希望生成前自动校验 130 条游戏的数量、字段和插画，以便错误在发布前暴露。
35. 作为内容维护者，我希望校验失败时看到具体游戏编号和缺失项，以便直接定位稿件问题。
36. 作为开发者，我希望应用代码不需要打包，以便改完刷新就能看到结果。
37. 作为开发者，我希望所有资源用相对路径，以便部署到 GitHub Pages 的子目录也不用改配置。
38. 作为开发者，我希望数据访问集中在一个接口后面，以便未来换成后端 API 时页面代码不动。
39. 作为未来的内容编辑，我希望新增“文字章”时复用同一套章节数据与块渲染，以便不用重写导航。

## Implementation Decisions

### 内容范围

- v0.1 只收录 14 个游戏章（第 5-18 章，130 个游戏）。第 1-4 章、第 19-21 章与 6 个附录不在本版范围。
- 章节模型保留 `kind` 字段（`games` / `prose`）。本版恒为 `games`；文字章在 v0.2 增加 `blocks`，不改变路由与导航。
- 章节顺序按书序线性排列：5→6→…→18；12→13 跨“篇”连续；首尾不循环。

### 分层与依赖

- 静态单页应用，原生 ES Modules，无框架、无打包器、无运行时依赖。
- 五类运行时模块：组合根、页面、展示组件、领域纯函数、数据访问；另有 DOM/router/store/focus 等基础设施。
- 依赖方向只能自上而下：组合根 → 页面 → 组件 → 基础设施；组合根 → 数据/状态；领域层零依赖。
- 只有组合根可以修改应用状态；页面与组件通过回调向上传递意图。
- 领域层不触碰 DOM、fetch、window，保证可直接用 Node 测试。
- 展示组件不读全局状态、不发请求；页面对象负责组合与页面级事件。

### 内容提取与数据契约

- 构建期扫描三个游戏章稿件，用逐行状态机识别“篇 → 章 → 游戏 → 字段”。
- 游戏标题决定编号与名称；紧随其后的信息条按分隔符切为六段：月龄、主能力、时长、场地、材料、人数。
- 步骤按 ①②③④ 切分，观察按中文分号切分；进阶与降阶在同一行，按字段标记切分。
- 章首非游戏内容解析为导语块；本版使用段落与无序列表两种块，其余块类型为文字章预留。
- 目录数据包含：数据版本、书稿版本、书籍信息、篇列表、章列表（章号、标题、短标题、月龄、游戏数、数据文件名）、130 条游戏索引（编号、名称、章号、月龄、能力）。
- 章节数据包含：数据版本、章号、标题、篇号、月龄、类型、导语块、游戏数组。
- 游戏字段固定为：编号、名称、月龄、月龄数值区间、能力、时长、场地、材料、人数、玩、步骤（4 条）、观察（2-3 条）、进阶、降阶、安全、问、主图、4 张步骤图。
- 插画路径相对页面文档解析，不相对章节数据文件；构建期生成，页面不得自行拼接。
- 生成前做硬校验：总数 130、编号唯一且连续、必填模块齐全、能力枚举合法、插画存在；任一失败不写出文件。
- 校验器与提取器分离，校验器只读产物，保证可以独立复检。
- 目录索引与章节内游戏必须一致：编号、名称、章号、月龄、能力逐条对账。

### 路由与历史

- 三条路由：目录 `#/`；章节 `#/ch/{章号}`；章节内游戏 `#/ch/{章号}/game/{游戏编号}`。
- 章号在 URL 中不补零；游戏编号保留两位字符串。
- 打开游戏弹层用 push，关闭弹层用 replace，避免“后退又打开弹层”的循环。
- 非法路由或不存在章节：replace 回目录，并显示一条短暂提示。
- 切章后滚动到顶部，焦点移到章标题；从弹层关闭后焦点回到触发卡片；深链进入时焦点落到游戏网格标题。
- 页面标题随路由更新：目录显示应用名与总数，章节显示章名。

### 加载、缓存与预取

- 首屏只请求目录数据；进入章节才请求该章数据；页面上同一时刻只渲染一章。
- 章节数据在内存中按章缓存；并发请求去重；成功常驻、失败剔除。
- 章节渲染完成后空闲 1 秒预取相邻两章，仅暖缓存、不渲染、不写状态；失败静默。
- 预取可以通过一个开关关闭，行为回到严格按需加载。
- 加载中显示骨架；失败显示错误块与重试；目录加载失败不渲染空目录。

### 状态与渲染

- 单一应用状态，包含：当前路由、目录资源状态、按章存放的章节资源状态、目录搜索词。
- 路由是导航的唯一来源；弹层是否打开由路由中的游戏编号派生，不另设布尔状态。
- 搜索词是纯 UI 状态，不写入 URL，刷新后清空。
- 每个资源独立维护“空闲/加载中/就绪/失败”，不做全局 loading。
- 选择器全部为纯函数：目录视图模型、章节视图模型、相邻章、搜索结果、当前游戏。
- 页面对象暴露“元素、更新、销毁”三个能力；搜索输入框只创建一次，更新时只替换结果区，避免输入丢焦点。
- DOM 一律通过 `textContent` 写入数据，禁止把数据拼进 `innerHTML`；导语中的粗体先按标记切段再建节点。
- 卡片必须是按钮元素，支持 Enter/Space；图片使用固定宽高比容器与懒加载，避免布局抖动。

### 导航与搜索

- 章节目录按“篇”分组；每章显示章号、标题、月龄、游戏数；不显示章节配图。
- 章节页顶部固定工具栏：目录、上一章、下一章；按钮直接显示目标章标题；底部再提供一次上一章/下一章。
- 搜索只匹配游戏名称，去首尾空格、忽略大小写；不做拼音、不做全文检索。
- 搜索结果展示游戏名、章号、月龄、能力；点击后进入对应章节并打开该游戏弹层。
- 搜索无结果时显示提示与清除按钮；搜索词不跨页面保留。

### 响应式与可访问性

- 三档断点：小于 640px、640-1023px、1024px 及以上；卡片列数分别为 1、2、3。
- 手机端游戏弹层全屏；平板 90% 视口；桌面最大 720px 居中。
- 章节工具栏在手机上压缩为三个等宽按钮，章标题单独一行。
- 首元素为跳转链接；路由切换后焦点到新页标题；弹层使用原生 dialog 的焦点圈定与 Esc 关闭。
- 搜索框为 search 类型并带可访问名称；结果计数使用 polite 播报。
- 桌面支持左右方向键切章，输入框内不拦截；不做手机左右滑动手势。
- 对比度不低于 4.5:1；不移除焦点环；尊重减少动效偏好。

### 错误处理

- 数据访问层把网络失败、HTTP 错误、JSON 解析失败、结构校验失败统一为带代码的应用错误，并标记是否可重试。
- UI 只按错误代码决定文案与是否显示重试，不解析后端错误消息。
- 目录失败：整页错误块；章节失败：章内错误块 + 重试；图片失败：同尺寸色块。
- 不存在的章节：回目录 + 提示；不存在的游戏编号：回该章并提示。

### 构建、部署与后端接缝

- 应用代码不做打包、不做压缩；浏览器直接加载源码模块。
- 构建只有数据管线：提取、校验、复制插画。npm scripts 提供数据生成、校验、本地服务、测试四个入口，零依赖。
- 类型通过 JSDoc 与编辑器配置获得，不引入 TypeScript 构建。
- 全相对路径 + hash 路由，静态托管无需重写规则，支持子目录部署。
- 目录与章节数据使用短缓存；插画使用长缓存。
- 数据访问层定义目录仓储接口：取目录、取章节、预热章节。页面只依赖领域对象，不关心来源是静态 JSON 还是 REST。
- 未来 REST 契约：取目录、取章节、按关键词搜索；响应使用 `data + meta` 信封，错误使用 `code + message` 信封；v0.1 不设计鉴权与跨域。

### 性能预算

- 体积预算（目录 / 单章 / 运行期 JS 未压缩）的数值以 `tools/budgets.mjs` 为唯一来源；图片大图功能把运行期 JS 预算上调了约 12 KB。
- 本地首屏可交互小于 1 秒；4G 小于 2.5 秒。
- 缓存命中的切章小于 50 毫秒；未命中时骨架在 100 毫秒内出现。
- 布局偏移小于 0.02。

## Testing Decisions

好的测试只验证外部可观察行为，不绑定内部实现：给定输入，断言输出、请求次数、缓存命中、错误代码与 DOM 可见结果；不 mock 私有函数，不测试 CSS 细节。

本版采用三个测试缝隙，全部选在已有边界上，不新增测试专用抽象：

1. **数据管线缝隙（最高层）**：对真实稿件运行提取与校验，断言 130 条、编号连续、8 模块齐全、能力合法、插画存在、目录索引与章节游戏逐条一致。这一层覆盖内容正确性，不测解析器内部正则。
2. **仓储缝隙**：注入假 fetch，断言目录/章节 URL 组装、并发去重、成功缓存、失败不缓存、错误归一为应用错误；断言预热只发请求、不产生渲染副作用。
3. **领域缝隙**：纯函数测试路由解析与生成（合法、非法、补零、越界）、搜索（大小写、空白、无结果）、相邻章（5 无上一章、18 无下一章、12→13 跨篇）、章节视图模型。

UI 层不做 DOM 单元测试，v0.1 用人工验收清单覆盖：三档断点无横向滚动、首屏只请求目录、进章后才请求章节、1 秒后出现相邻章预取、目录↔章节两次点击内完成、后退关闭弹层、深链刷新、焦点返回、断网重试。

仓库当前没有既有测试，先例为零；使用 Node 内置测试运行器，测试文件与被测模块同层组织，不引入测试框架依赖。数据校验同时作为发布前门禁，失败即阻断。

需要与需求方确认的正是这三处缝隙：数据管线、仓储、领域纯函数。若认为 UI 行为需要自动化，可在 M4 增补浏览器端冒烟测试，作为第四个缝隙，但不进入 v0.1 必做范围。

## Out of Scope

- 第 1-4 章、第 19-21 章、前置内容与 6 个附录的阅读页
- 收藏、打卡、游戏记录、账号、云同步
- PWA、Service Worker、离线阅读
- 拼音搜索、全文检索、材料/玩法搜索
- SEO、SSR、History API 路由、多页面预渲染
- 手机左右滑动切章
- 打印排版、PDF 导出
- 内容在线编辑、后台管理
- 后端 API 实现、鉴权、跨域配置
- 多语言
- 数据可视化、成长曲线

## Further Notes

- 内容唯一来源是书籍仓库的 Markdown 稿件（书稿版本 v1.4）；网页数据是产物，禁止手改。
- 数据更新流程固定为：改稿 → 重新提取 → 校验 → 提交产物；页面无需改动。
- 本版假设不需要搜索引擎收录，因此选择 hash 路由；若后续需要 SEO，应改为预渲染多页，属于架构级变更。
- 本版假设单章内容与单章游戏数都在 `tools/budgets.mjs` 的阈值内；超过时重新评估是否需要虚拟滚动或分页。
- 预取是性能优化，不是内容加载语义的一部分；如对“一次只加载一章”有更严格的解释，可关闭预取而不影响功能。
- 架构方案 v0.2 已记录在仓库文档中，包含数据契约字段、错误码、验收清单与决策权衡；本 spec 是其可执行摘要。
