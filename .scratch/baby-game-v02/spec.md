# babyGame v0.2 — 全书章节补齐

Status: ready-for-agent
Source: 2026-10-20 设计评审（Q1-Q5 按推荐）
Related: ADR-0001「文档模型与路由：统一“文档”，保留 `#/ch/{n}`」

## Problem Statement

家长手里有《0-3岁亲子游戏图鉴》，但网页只收录第 5-18 章的 130 个游戏。想读“为什么玩比教有效”、想知道祖辈怎么接手、想查发育里程碑或安全清单时，仍然只能翻纸书；目录也看不出书有前置、四篇正文和附录。临到要用的时候，家长还是得回到纸书，网页只解决了一半问题。

## Solution

把全书补齐为一个可连续阅读的网页：目录按“前置 / 第一篇 / 第二篇 / 第三篇 / 第四篇 / 附录”分组，列出 21 章与 6 个附录；点进任一文档只加载该文档；文字章按正文、表格、清单的原样排版呈现，宽表可横向滚动，清单可勾选；顶部与底部始终可以回目录、翻上一页/下一页，顺序从“前置”一直走到“附录F”；目录搜索同时覆盖 130 个游戏与所有文档标题；每个文档有稳定链接，可分享、可刷新、可后退。游戏章的卡片、详情弹层与大图体验保持不变。

## User Stories

1. 作为家长，我希望目录同时列出前置、四篇正文与附录，以便一眼看出这本书的完整结构。
2. 作为家长，我希望目录仍按“篇”分组，而不是一串 28 条平铺，以便按书的逻辑找内容。
3. 作为家长，我希望前置单独成组，以便先读序、使用说明与发展地图。
4. 作为家长，我希望第 1-4 章出现在目录里，以便先理解游戏观、五个标准、时机与材料安全。
5. 作为家长，我希望第 19-21 章出现在目录里，以便找到祖辈带娃、早产/发育偏慢、屏幕边界的内容。
6. 作为家长，我希望附录 A-F 各自独立成条，以便直接查里程碑、安全清单、索引、书单、儿歌与记录页。
7. 作为家长，我希望目录行能区分“几个游戏”和“阅读”，以便点开前就知道会遇到卡片还是长文。
8. 作为家长，我希望点目录里的任一文档都能直接打开，以便导航方式在所有内容上保持一致。
9. 作为家长，我希望一次只加载当前文档，以便在移动网络下不浪费流量。
10. 作为家长，我希望进入文字章后看到章节标题、所属篇和小节导航，以便知道自己在书里的位置。
11. 作为家长，我希望小节导航能跳到“2.3 重复是刚需”，以便不用长距离滚动。
12. 作为家长，我希望在手机上小节导航默认折叠，以便不挡住正文。
13. 作为家长，我希望正文行宽和行高适合连续阅读，以便在手机上读两千字不累。

19. 作为家长，我希望有一键“重置本页勾选”，以便下个月或第二个孩子重新用。

48. 作为开发者，我希望游戏章的既有深链继续可用，以便这次扩展不破坏已分享的链接。
49. 作为开发者，我希望测试继续落在既有三处缝隙上，以便不新增测试框架与 DOM 测试负担。

## Implementation Decisions

### 1. 内容范围与文档模型

- 全书共 28 个文档：前置 1 个、第 1-21 章 21 个、附录 A-F 6 个。
- 第 5-18 章是游戏章（`kind: "games"`），沿用现有 130 个游戏；第 1-4、19-21 章是文字章（`kind: "prose"`）。
- 前置包含序、本书使用说明、0-36 个月发展地图三节，合成 1 个文档；不拆成 3 页。
- 附录 A-F 各自独立成文档，共 6 个；不合并成 1 页。
- `captions.md` 不属于文档模型。它是 130 条游戏图注，按游戏 id 并入游戏详情是后续独立决策。
- 文字章没有配图；本次不新增章节插画、封面图或游戏图。文字章页头使用纯排版标题。
- 全书阅读顺序固定为：`front` → `ch01`…`ch21` → `apx-a`…`apx-f`。所有分组、相邻页、预取与搜索排序都以这份顺序为唯一依据。
- 文档 id 稳定：`front`、`ch01`…`ch21`（两位补零）、`apx-a`…`apx-f`（小写）。
- 目录 `book` 计数：`total: 130`、`chapterCount: 21`、`docCount: 28`。
- 游戏章的数据字段保持现状，只增加文档级的 `id`、`kind` 与分组信息；不改游戏 8 模块、4 步、2-3 条观察与插画路径。

### 2. 数据契约

目录数据版本升到 2，形状如下（示意，未列全）：

```jsonc
{
  "schemaVersion": 2,
  "bookVersion": "v1.4",
  "book": { "title": "…", "subtitle": "…", "total": 130, "chapterCount": 21, "docCount": 28 },
  "groups": [
    { "id": "front", "title": "前置", "docIds": ["front"] },
    { "id": "part-1", "no": 1, "title": "会玩的孩子", "docIds": ["ch01", "ch02", "ch03", "ch04"] },
    { "id": "part-2", "no": 2, "title": "分月龄游戏图鉴", "docIds": ["ch05", "…", "ch12"] },
    { "id": "part-3", "no": 3, "title": "把游戏放进生活", "docIds": ["ch13", "…", "ch18"] },
    { "id": "part-4", "no": 4, "title": "不同家庭的玩法", "docIds": ["ch19", "ch20", "ch21"] },
    { "id": "appendix", "title": "附录", "docIds": ["apx-a", "…", "apx-f"] }
  ],
  "docs": [
    {
      "id": "ch05",
      "no": 5,
      "kind": "games",
      "title": "0-3个月｜躺着的世界",
      "shortTitle": "躺着的世界",
      "meta": "0-3月",
      "count": 10,
      "file": "…"
    }
  ],
  "gameIndex": [{ "id": "01", "name": "黑白卡追视", "docId": "ch05", "chapterNo": 5, "age": "0-3月", "ability": "认知探索" }]
}
```

约定：

- `groups` 只引用文档 id，不重复存标题与计数；`docs` 是唯一有序列表，分组顺序与 `docs` 顺序必须一致。
- `docs[]` 字段固定：`id`、`no`（无章号为 null）、`kind`、`title`、`shortTitle`、`meta`、`count`、`file`。
- `meta` 是目录行上的补充标签：游戏章写月龄或“生活场景”；文字章写“阅读”；附录写“附录”；前置写“阅读”。
- `gameIndex` 的 `docId` 取代原来的 `chapterNo` 作为主关联；`chapterNo` 保留给搜索结果的“第 N 章”展示与旧逻辑过渡。
- 编号章的数据文件沿用既有章节数据目录；无编号的前置与附录使用文档数据目录。`file` 字段是页面取数的唯一入口，页面不得自行拼接路径。
- 目录 JSON 压成单行写入；单章/单文档 JSON 保留缩进便于排查。

文档数据版本同为 2。两种形状：

```jsonc
// 游戏章
{
  "schemaVersion": 2, "id": "ch05", "no": 5, "kind": "games",
  "title": "…", "partId": "part-2", "meta": "0-3月",
  "intro": [Block], "games": [Game]
}

// 文字章 / 前置 / 附录
{
  "schemaVersion": 2, "id": "ch01", "no": 1, "kind": "prose",
  "title": "…", "partId": "part-1", "meta": "阅读",
  "blocks": [Block],
  "sections": [{ "id": "s1", "level": 3, "title": "1.1 0-3岁，大脑在忙什么" }]
}
```

块契约：

```jsonc
Block =
  | { "type": "p", "text": "…" }
  | { "type": "h2" | "h3" | "h4", "text": "…" }
  | { "type": "ul", "items": ["…"] }
  | { "type": "ol", "start": 9, "items": ["…"] }
  | { "type": "table", "head": ["…"], "rows": [["…"]] }
  | { "type": "quote", "text": "…" }
  | { "type": "checklist", "items": [{ "text": "…", "checked": false }] }
  | { "type": "hr" }
```

- 文本字段只支持一种行内标记：`**粗体**`。其余 Markdown（链接、图片、代码、斜体、原始 HTML）不进入契约；遇到即构建失败，不静默丢弃。
- 段落中的硬换行保留为 `\n`，渲染为 `<br>`；普通换行按新段落处理。
- “独占一段且整段加粗”的段落升级为 `h4`，条件是：整行只由一个 `**…**` 组成、内部不含 `*`、不以 `。！？；` 结尾、长度不超过 40 字。不满足则保留为带粗体的段落。当前稿件有 183 处这种伪标题。
- 有序列表必须带 `start`，取该组第一项的原始编号；跨块连续编号（附录 D 的 1-50、附录 E 的 1-30）靠这个字段保真。
- 表格保存 `head` 与 `rows`，不保留对齐标记；每个 `rows` 项的长度必须等于 `head` 长度。
- 清单项保存 `text` 与稿件默认 `checked`；网页勾选状态不写回数据。
- `sections` 由标题块按出现顺序派生，`id` 为 `s1`…`sn`，`level` 为 2/3/4，供页内导航滚动使用；v0.2 不为小节生成 URL 深链。
- `intro` 仍只用于游戏章；`blocks` 只用于文字章；两者不混用。

### 3. 路由与导航

路由表：

| hash | 含义 |
|---|---|
| `#/` | 目录 |
| `#/front` | 前置 |
| `#/ch/{1..21}` | 第 1-21 章（游戏章或文字章） |
| `#/ch/{n}/game/{id}` | 游戏章内的游戏详情 |
| `#/appendix/{a..f}` | 附录 A-F |

- 内部路由统一为“目录”与“文档”两种：文档路由携带 `docId`，游戏详情再携带 `gameId`。页面不再直接处理章号。
- `#/ch/5`、`#/ch/05`、`#/ch/5/game/01` 继续可用，已有分享链接不失效。`#/appendix/A` 大小写不敏感，归一为小写。
- 非法文档 id、越界章号、不存在的附录：replace 回目录并提示；游戏 id 不属于该章：replace 回该章并提示。
- 上一页/下一页按全书顺序线性推进：`front → ch01 → … → ch21 → apx-a → … → apx-f`；第 4→5、12→13、18→19 连续；首尾禁用，不循环。
- 导航文案统一为“上一页 / 下一页”，目标标签用文档标签：`第N章 短标题`、`前置：序、使用说明、发展地图`、`附录A 短标题`。禁用时显示“已是第一页 / 已是最后一页”。
- 打开游戏弹层仍用 push，关闭用 replace；文字章没有弹层，浏览器后退直接回上一文档或目录。
- 切换文档时销毁上一页的弹层、大图查看器与监听；页面 key 使用 `doc:{docId}`。
- 桌面左右方向键切文档；焦点在输入框、复选框等表单控件内时不拦截。

### 4. 加载、缓存与状态

- 应用状态把 `chapters` 改为 `docs`，以 `docId` 字符串为键：`{ status, data, error }`。
- 首屏仍只请求目录；进入文档才请求该文档 JSON；同一时刻只渲染一个文档。
- 文档缓存按 id 常驻；并发请求去重；失败剔除，允许重试。
- 文档渲染完成后空闲 1 秒预取前后各一个文档；只暖缓存，不写状态、不渲染；失败静默。
- 只有组合根修改状态；页面与组件只上抛意图。selectors 保持纯函数，输出文档视图模型、相邻页、搜索结果与当前游戏。
- 目录加载失败不渲染空目录；文档加载失败显示文档内错误块与重试；图片失败的处理沿用现有游戏卡逻辑。
- 搜索词仍是纯 UI 状态，不写入 URL，刷新后清空。

### 5. 页面与组件

- 新增文字章页面，与游戏章页面并列；两者共用工具栏、骨架/错误态、相邻页选择器与页脚导航。
- 游戏章页面只做“章号 → 文档 id”的适配与导航文案调整，卡片、弹层、大图、焦点恢复逻辑保持不变。
- 文字章页面结构：固定工具栏 → 页头（所属篇、标题、meta）→ 小节导航 → 正文块 → 页脚上一页/下一页。
- 小节导航：桌面 ≥1024px 为侧边吸顶栏，正文与小节导航两列；小于 1024px 折叠为正文上方的 `<details>`。小节超过 12 项时侧栏独立滚动。
- 小节导航使用按钮 + `scrollIntoView`，**不使用 `#section` 锚点**，因为 hash 归路由所有；URL 保持不变。
- 正文排版：正文用衬线字体，行高 1.9，单行约 38 个汉字；段落不首行缩进，用段间距分隔；标题层级 h2/h3/h4 逐级递减；所有标题设置 `scroll-margin-top`，避免被吸顶工具栏遮住。
- 文字章页头不显示游戏数；显示所属分组与 `meta`。前置标题为“前置｜序、使用说明、发展地图”；附录标题保留“附录A …”，目录行可用短标题。
- 页脚与工具栏的上一页/下一页使用同一套文档标签函数，避免两处文案不一致。
- 组件仍遵循“纯 props → DOM、回调向上、文本走 textContent”的既有契约；数据不得拼进 `innerHTML`。

### 6. 块渲染与表格

- 段落、标题、无序/有序列表、引用、清单、分隔线均用语义元素渲染；`ol` 使用 `start` 属性。
- 表格保留 `<table>` 语义，外层包一个可横向滚动的区域：`overflow-x: auto`、`tabindex="0"`、`role="region"`、`aria-label` 取最近标题或“数据表”。
- 宽表在 360px 下只让表格容器横向滚动，页面本身不得出现横向滚动；第一列使用 sticky 固定在左侧；表头不吸顶，避免嵌套纵向滚动。
- 清单用原生 `<input type="checkbox">`，每项用 `<label>` 包裹文本；清单块外层加 `aria-label`，说明这是可勾选清单。
- 引用块保留换行；多行引用渲染为块内换行，不拆成多个块。
- 标题、表格单元格与清单项内的 `**…**` 都要解析为 `<strong>`；其余 `*`、`_`、反引号按字面文本输出。
- 空表格单元格保留占位，附录 F 的空白记录表在网页上仍可辨认行列。
- 不支持嵌套列表、图片、代码块、原始 HTML；提取阶段遇到即报错并指出文档与行号。

### 7. 清单勾选状态

- 稿件里的 `checked` 只是默认值；网页状态按文档 id 存在浏览器本地，键为 `babyGame:checklist:{docId}`。
- 存储内容以“块索引:项索引”为键，只保存已勾选项；读取时忽略越界或未知键，块结构变化不会导致页面崩溃。
- 文档页头在包含清单的文档上显示“重置本页勾选”；点击清除该文档的本地状态并取消所有勾选。
- `localStorage` 不可用或写入失败时静默降级：本次会话内仍可勾选，刷新后丢失，不弹错误。
- 勾选状态不跨设备同步，不写回数据文件，不影响搜索与目录。

### 8. 搜索

- 搜索范围从“130 个游戏名”扩展为“130 个游戏名 + 28 个文档标题/短标题”。
- 匹配规则：去首尾空格、忽略大小写、子串匹配；不做拼音、不做全文检索、不做搜索高亮。
- 排序：完全匹配 → 前缀匹配 → 包含匹配；同分按全书顺序；同一文档内游戏结果排在文档结果之前。
- 结果项显示：主标题、类型标签（游戏 / 章节 / 附录 / 前置）、补充信息（游戏显示月龄与能力；文档显示章号或“附录”）。
- 点击游戏结果进入对应章节并打开游戏弹层；点击文档结果进入该文档。
- 结果计数文案改为“找到 N 条结果”；无结果文案改为“没有找到匹配的内容”，并保留清除按钮。
- 搜索索引仍内嵌在目录 JSON 中，不新增请求；目录体积预算不因搜索拆包而改变。

### 9. 提取与校验

- 提取器新增文字稿件解析能力，与现有游戏解析共用同一套数据集组装与校验入口；不引入运行时依赖。
- 输入稿件：前置、第一篇两章文件、第四篇文件、附录文件，加上既有三份游戏章稿件。输出 28 个文档与 130 个游戏。
- 章节边界：`## 第N章 …` 开始一个编号文档；`# 第X篇 …` 只用于确定分组，不产出正文块；`---` 丢弃。
- 前置：固定 id `front`，标题合成；三个 `##` 标题成为 `h2` 块。
- 附录：按 `## 附录X …` 拆成 6 个文档；标题从该行取，id 由字母转小写；正文中的整段加粗升级为 `h4`。
- 第一个章标题之前的内容、最后一个章标题之后的内容都归入相邻文档；不得静默丢弃。
- 连续 `- ` 行合并为一个 `ul`；连续 `- [ ]` / `- [x]` 合并为一个 `checklist`；连续 `1. ` 行合并为一个 `ol`，`start` 取第一项编号；连续 `|` 行解析为一个 `table`，第二行分隔行丢弃；连续 `>` 行合并为一个 `quote`。
- 整段加粗升级规则见第 2 节；不满足条件的保留为段落。
- 校验必须覆盖：28 个文档、21 章、6 附录、1 前置；文档 id 唯一；`docs` 顺序与分组顺序一致；分组恰好覆盖每个文档一次；130 个游戏仍在第 5-18 章；文字章 0 个游戏；每个文字章至少 1 个块；标题非空；表格行宽一致；有序列表 `start` 为正整数；清单项非空；不得残留字面 `[ ]`；不得出现图片/代码/原始 HTML。
- 当前内容基线作为验收点：附录 B 的 37 项清单全部解析为 checklist；附录共 13 张表，最宽 5 列；附录 D 的 1-50、附录 E 的 1-30 跨块编号连续；附录 E 的童谣段落保留换行。
- 错误信息必须包含文档 id 与块序号或源行号，例如“ch03 第 12 块：表格列数不一致（表头 4 列，第 3 行 3 列）”；任一错误都不写出文件。
- 构建成功后重写全部目录与文档数据；旧版本章节/文档文件若不再被目录引用，应清理，避免部署出孤儿数据。
- 提交的数据产物必须与重新提取结果一致；不允许手工改 JSON。

### 10. 体积预算与性能

- 目录预算保持 20 KB（预计约 17 KB）；单文档预算保持 45 KB（附录预计约 25 KB）。
- 运行期 JS 未压缩预算从 56 KB 上调到 72 KB；理由：新增文字章页面、块渲染器、小节导航与清单状态约 15 KB。预算数值仍由一个唯一来源提供给校验脚本与发布测试。
- 首屏请求仍只有 HTML、CSS、入口 JS 与目录 JSON；进入文档后才请求该文档；预取只暖缓存。
- 缓存命中的文档切换 < 50ms；未命中时骨架 < 100ms 出现；布局偏移 < 0.02。
- 表格与清单不得引入第三方库；滚动与勾选都用原生能力。

### 11. 响应式与可访问性

- 三档断点沿用：<640px、640-1023px、≥1024px；文字章在手机单列，平板上限宽，桌面正文 + 侧边小节导航。
- 360px 下页面无横向滚动；只有表格容器可横向滚动。正文单行不超过约 38 个汉字，桌面不因宽屏拉成长行。
- 路由切换后焦点落到新文档 `h1`（`tabindex="-1"`）；工具栏、页脚、搜索结果的按钮都有可访问名称。
- 工具栏 `aria-label` 为“文档导航”；上一页/下一页禁用时仍保留可读状态。
- 小节导航是 `<nav aria-label="本页目录">`；移动端 `<details>` 的 summary 可键盘展开。
- 表格滚动区域可 Tab 聚焦，读屏能读出区域名称；表头用 `<th scope="col">`。
- 清单项的原生 checkbox 必须有对应 label；重置按钮有明确名称。
- 对比度 ≥ 4.5:1；不移除焦点环；`prefers-reduced-motion` 下关闭过渡与滚动动画。
- 支持键盘：Tab 顺序自然，左右方向键切文档，Esc 仍只关闭游戏弹层/大图；文字章没有弹层。

### 12. 文档

- 本次已新增根词汇表，收录“文档 / 游戏章 / 文字章 / 前置 / 附录 / 小节 / 块”。

- 发布文档的验收清单补充：28 个文档全部可打开、全链路翻页、宽表横向滚动、清单勾选与重置、深链刷新、360px 无页面横向滚动。
- 文档与代码冲突时，以本 spec 与 ADR-0001 为准；实现完成后再回写架构文档。

## Testing Decisions

好的测试只验证外部可观察行为：给定输入，断言输出、请求次数、缓存命中、错误代码与数据形状；不 mock 私有函数，不测试 CSS 细节，不绑定组件内部结构。

本版**不新增测试缝隙**，沿用 v0.1 已建立的三处：

1. **数据管线缝隙（最高层）**：对真实稿件运行完整提取与校验，断言 28 个文档、21 章、6 附录、130 个游戏、顺序、分组覆盖、块类型、表格形状、清单数量、跨块编号、提交产物与重新提取一致。这一层覆盖解析器与校验器的正确性，不测正则内部。
2. **领域纯函数缝隙**：路由解析/生成（`#/front`、`#/appendix/a`、`#/ch/1`、游戏深链、非法输入、大小写与补零）、全书相邻页（首尾、4→5、12→13、18→19、21→附录A）、搜索排序与结果类型、文档标签、清单状态的编码/解码。先例是现有路由、目录、格式化与选择器测试。
3. **仓储缝隙**：注入假 fetch，断言文档 id 到文件路径的组装、并发去重、成功缓存、失败不缓存、错误归一为应用错误、预取只发请求不产生渲染副作用。先例是现有目录/章节仓储测试。

发布门禁沿用并扩展：扫描编号章与无编号文档两个数据目录做体积检查；运行期 JS 预算按新值检查；相对路径、`innerHTML`、图片路径与十六进制颜色的既有检查继续生效。

UI 层不做 DOM 单元测试，由人工验收覆盖：

- [ ] 360px / 768px / 1440px 无页面横向滚动；表格容器可横向滚动，第一列保持可见。

- [ ] 文字章标题、表格、清单、引用、跨块编号与童谣换行与稿件一致。

## Out of Scope

- 把 `captions.md` 的 130 条图注并入游戏详情。
- 新增文字章插画、章节封面图或游戏图。
- 小节级 URL 深链（`#/ch/2/s/3`）与小节分享。
- 清单状态跨设备同步、账号、云存储；也不写回 Markdown。
- 全文检索、拼音搜索、材料/玩法搜索、搜索高亮。
- 把宽表改写成卡片或分组列表；保留表格语义。
- 前置拆成 3 页、附录合并成 1 页。
- 打印排版、PDF 导出、离线/PWA、Service Worker。
- 自动把“第 21 章会详细讲”这类正文交叉引用改成链接。
- SEO、SSR、History API 路由、多页面预渲染。
- 内容在线编辑、后台管理、内容版本对比。
- 游戏章内容改写、130 个游戏的重新分类或图注补齐。
- 多语言、深色模式、主题切换。

## Further Notes

- 内容唯一来源仍是书籍仓库的 Markdown 稿件（书稿版本 v1.4）；网页数据是产物，禁止手改。数据更新流程固定为：改稿 → 重新提取 → 校验 → 提交产物。
- `book/book.html` 是同一批稿件的印刷版渲染结果，可作为块层次与文案的参照，但不是运行期依赖；网页数据仍从 Markdown 解析。
- 关键假设：前置 1 页、附录 6 页、文字章无配图、`#/ch/{n}` 保持兼容、清单只做本地状态。若其中任一项要改，先改 ADR-0001 与本 spec 再实现。
- 已知风险：稿件里的伪标题与表格是解析器最容易退化的地方，校验器必须给出文档 id 与行号；目录从 14 条章记录扩到 28 条文档记录，需守住 20 KB；文字章渲染器会让运行期 JS 接近新预算，后续再加功能前先看预算。
- 实现顺序建议：先让数据管线产出 28 个文档并通过校验，再做路由/状态/仓储，再做文字章页面与块渲染，最后补搜索、清单、样式与人工验收；每一步都保持游戏章可运行。
- 完成定义：三处测试缝隙全绿、发布门禁全绿、人工验收清单全过、架构文档更新到 v0.3、ADR 与词汇表已入库。
