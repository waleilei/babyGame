# 步骤图与提示词对齐

**Status:** ready-for-agent
**Slug:** panel-prompt-alignment
**Owner:** babyGame（内容资产侧），书稿仓只作为图片的产出地与归档地

---

## Problem Statement

读者打开任意一个游戏章，会看到四张**步骤图**。这四张图应该演示这个游戏的四步玩法。

现在的问题是：书里 520 张步骤图，**是按已经归档的旧总表生成的，现行提示词从来没有用于出图**。证据有三条：

- 生成原件文件名写的是旧词的开头（「暖米色调，淡彩晕染，柔光」），而现行共享层写的是「高调低饱和暖米色调，湿画法晕染」——两者不是同一版文本。
- `058-3` 画面里有一只活的小猫，现行提示词里没有猫，旧总表这一格写的正是「妈妈指小猫学『喵』」。
- `036-1` 坡顶摆着绕珠玩具，现行道具是「软球 1 个」，旧总表这一格写的是「妈妈在坡顶放玩具」。

抽查到的偏差率在三到四成：有的图多了旧版才有的道具，有的换了场景，有的把动作画反了方向。对读者来说，这意味着「图说的」和「文字说的」不是一回事；对维护者来说，这意味着**没人能说清某张图是故意画成这样，还是旧词残留**。

更麻烦的是追溯：现在没有任何记录说明「这张图是哪一版提示词、哪一天、按什么理由生成的」。改一张图，旧图就没了；想知道改过什么，只能翻 git。

## Solution

按**章节 → 游戏 → 步骤图**的顺序，把 520 张图逐一比对现行提示词，不一致的重画，一致的留用；每一批的比对结论、改与不改的理由、新旧图片的指纹，都落到一份可核对的清单里。

具体是四件事：

1. **一批一章，一游戏一组**。以游戏章的 14 个游戏章为批次单位，章内以游戏为单位推进；一个游戏的 4 张步骤图作为一个整体看，不拆开改。
2. **先比对，再动手**。每张图给出「通过 / 重画」的判定和理由码；判定为重画的，才进入生成环节。
3. **先校准，再铺开**。每章先画 1 张，与现有图的风格并排比对，通过后才批量生成；不通过就把整章标为阻塞，不拿风格不一的图凑数。
4. **每格一行账**。每张图在清单里占一行：用了哪版提示词（哈希）、为什么改、旧图指纹、新图指纹、属于哪一批、第几次尝试、谁验的。

做完之后，任何人拿到清单就能回答三个问题：这张图为什么长这样、它替换掉了什么、还有哪些格子没处理。

## User Stories

1. 作为**读者**，我希望步骤图画的就是这一步该做的事，这样我照着图做不会做错。
2. 作为**读者**，我希望图里的道具和正文器材一致，这样我不会去找一个书里根本没让我准备的东西。
3. 作为**读者**，我希望 0-3 个月的宝宝不会被画成能坐、能爬，这样我不会对孩子的能力产生错误期待。
4. 作为**读者**，我希望步骤图不出现安全条明令禁止的姿势，这样我不会照着图做出危险动作。
5. 作为**家长**，我希望四张图连起来是一个能照着做的流程，这样我不用反推顺序。
6. 作为**作者**，我希望每一格画面都能追溯到一条提示词，这样我改正文时知道哪些图要跟着改。
7. 作为**作者**，我希望能看到「这一章还有几格没核对」，这样我知道离完成还有多远。
8. 作为**编辑**，我希望每一处重画都有理由码（场景/道具/动作/月龄/安全/禁画项），这样可以按理由归类复查。
9. 作为**编辑**，我希望被替换的旧图还能找回来，这样判错了可以回滚。
10. 作为**编辑**，我希望风格不一致的批次直接停下来找我，而不是自动铺满，这样整本书不会花掉。
11. 作为**美术**，我希望重画时用的风格前缀与共享层逐字一致，这样新旧图能放在同一本书里。
12. 作为**美术**，我希望知道这一批用的是什么生成参数，这样我能复现或微调。
13. 作为**审核者**，我希望复核者看不到「改之前是什么」，只看图与提示词，这样不会被前一次的判断带偏。
14. 作为**审核者**，我希望每一格只有一个明确状态，这样我不必猜它是不是已经改过。
15. 作为**维护者**，我希望一条命令就能验证「键、图、提示词、清单」四者一致，这样回归不靠人眼。
16. 作为**维护者**，我希望提示词一改，对应的清单行自动失效，这样不会出现「图还是旧词的、账却是新词的」。
17. 作为**维护者**，我希望批次可以中断续跑，这样不必一次做完 520 格。
18. 作为**维护者**，我希望重画失败重试两次就停，不留半成品覆盖原图。
19. 作为**维护者**，我希望清单是纯文本、可 diff 的，这样评审能看出这一批动了哪些格子。
20. 作为**发布者**，我希望发布前能确认「没有未记账的图片变更」，这样不会把没核过的图发出去。
21. 作为**发布者**，我希望图片尺寸、比例、命名保持不变，这样前端与排版不用改。
22. 作为**新接手的人**，我希望有一份现状说明，讲清「现有图出自旧总表」这个前提，这样我不会误以为图与提示词本来就是一一对应的。
23. 作为**新接手的人**，我希望知道哪些章已经对完、哪些章还有分歧，这样我能接着做。
24. 作为**批处理执行者**，我希望每一批有明确的进入条件，这样我不会在图还没比对完时就开始生成。
25. 作为**批处理执行者**，我希望一个游戏的四张图要么全过、要么整组打回，这样同一组图不会新旧混用。

## Implementation Decisions

### 权威顺序

**章节正文 > 插画脚本 > 数据 JSON > 现有图片。** 提示词服务于正文；提示词与正文冲突时先改提示词（本 spec 之前已完成 33 格对齐），再按提示词改图。图片不作为事实来源，只作为风格与构图参考。

### 批次单位

- 一级批次 = 一个游戏章，编号形如 `ch08-b01`。
- 二级单位 = 一个游戏的四张步骤图，整组判定、整组生成、整组验收；不做单格替换。
- 单个生成批次的重画上限为 10 张。超过则拆成 `ch08-b02`、`ch08-b03`。

### 清单（manifest）

每章一份清单，每格一行，纯文本、可 diff。字段固定：

```text
key,prompt_hash,decision,reason,old_sha256,new_sha256,batch,attempt,status,ts
036-1,<sha1 of composed prompt>,regen,A2-prop,<sha256>,<sha256>,ch08-b01,1,verified,2026-10-21T09:12:00+08:00
```

- `decision`：`pass` / `regen`。
- `reason`：`P0-pass` / `A1-scene` / `A2-prop` / `A3-action` / `A4-age` / `A5-safety` / `A6-forbidden` / `A7-style`（2026-10-21 增补：画风跑偏归 A7，不再寄 A4）。
- `prompt_hash`：对**拼接后的完整提示词**取哈希，而不是对格层字段。提示词一改，该行自动失效，必须重新比对。
- `status`：`audited` / `regenerated` / `verified` / `needs-human` / `blocked`。
- 一个 key 只允许一行；重画失败重试时更新 `attempt`，不新增行。

### 批次状态

每章一份状态记录：`pending → audited → calibrating → regenerating → verifying → done`，任一步失败进入 `blocked` 并写明原因。状态只由清单与备份目录推导，不单独维护第二份真相。

### 备份与回滚

- 覆盖任何一张图之前，先把原图按 `sha256` 复制到不可变备份区，命名保留原 key。
- 回滚 = 按清单里的 `old_sha256` 找到备份、写回、把该行状态改回 `audited`。
- 没有备份与清单行，不允许覆盖；这条是硬规则，优先于任何批量脚本的便利性。

### 图片产出规格

- 画幅 3:2，与现有图一致（网页用 900×600 JPG，质量 90；书稿仓另存 1536×1024 PNG 原件）。
- 文件名沿用 `NNN-K`，不新增、不改名、不改目录层级；键与图片的双向一致性由既有校验保证。
- 生成时必须逐字使用共享层的风格、人物、负面层文本；批次记录里写明所用的生成参数。
- 已知右下角「AI生成」水印是当前生成器的签名，不作为缺陷处理，也不裁切。

### 风格校准门

每一章铺开前先画 1 张，与同场景的现有图并排比对：色调、纸纹、轮廓线、人物面部与手部、光位。通过才批量生成；不通过则该章标 `blocked`，交人判断。校准结果（通过/不通过、差异点）写进批次记录。

### 校验接缝

**最高接缝：沿用现有的统一校验入口。** 不新开一条命令链。在现有提示词校验里增加一段「清单校验」，与「键与图片双向一致」「字典引用」「月龄对齐」并列，这样一次校验就能回答「提示词、图片、清单是否自洽」。

清单校验要覆盖：每个 key 至多一行（缺行即未处理，只进覆盖统计，不报错——2026-10-21 放宽，支持逐游戏推进与跨章插队）；`status` 在枚举内；`prompt_hash` 与当前拼接结果一致；`regen` 行必须有新旧两个指纹；`verified` 行的新图指纹必须等于磁盘上图片的指纹；备份区里必须存在对应的 `old_sha256`。

### 生成失败策略

单张最多两次尝试。两次都未通过，标 `needs-human`，保留原图，不覆盖，继续处理下一格。批次结束时汇总 `needs-human` 清单。

### 复核方式

- 自动：上面的清单校验 + 现有的全量校验。
- 人工/半自动：只对**改过的**图做第二轮盲审——复核者只看图与提示词，不看清单与旧图，按同一套理由码给结论；结论与清单不一致的，回到 `needs-human`。
- 重画批次自 2026-10-21 起按 `.scratch/panel-anchoring-rollout/runbook.md` 的锚定规程执行：参考图选序、锚定 key 记入盲审记录首行、盲审例检「被参考图带偏」。

## Testing Decisions

**好的测试只验证外部行为**：给一份清单和一组图片，能不能判定「这批可发布」。不断言内部函数、不断言生成模型。

**被测模块**：清单校验（新增于现有校验入口内）、备份与回滚、批量状态推导。

**测试类型与先例**：

- 清单校验用表格驱动：缺行、重复 key、状态越界、`prompt_hash` 过期、`regen` 缺指纹、备份缺失、`verified` 指纹与磁盘不符——每种一个用例。先例是现有提示词校验里「键与图片双向一致」的正反用例。
- 回滚用临时目录做端到端：覆盖 → 回滚 → 指纹回到原值。
- 批次状态推导用纯数据输入，不触碰真实图片。

**不做自动化的部分**：画面像不像、风格是否统一。这部分只能用盲审 + 理由码，且必须接受「同一张图两人判断不同」的可能，分歧即升级。

## Out of Scope

- 修改章节正文、图注、插画脚本。
- 修改 `data/` 下的游戏数据与抽取逻辑。
- 修改共享层（风格、人物、镜头、场景、负面）的任何文本。
- 修改归档的旧总表。
- 重新排版 PDF、重新导出书稿成品。
- 为「好看的构图」而重画：只处理与提示词不一致的格子，不追求审美升级。
- 把 520 张图一次性重做：本 spec 明确按章分批、按需重画。

## Further Notes

- 本 spec 之前已完成提示词侧的第一轮对齐：11 个章文件、33 格动作描述按正文修正，`npm run check` 保持 0 错误 0 警告。这批改动是图片比对的前提，不应再回退。
- 首轮比对的可信度有限：分章代理给出的 A 级数量偏高，且部分输出被截断。执行时不要直接采信历史结论，**以清单里的逐格判定为准**，历史结论只作线索。
- 现有图片出自旧总表这件事本身要写进 ADR，否则下一轮还会有人默认「图与提示词一一对应」。
- 已知需要重点关注的格子集中在「由正文步骤改写、而非由插画脚本迁入」的约 20 个游戏，它们最容易出现动作与步骤错位。
