# babyGame v0.4 — 游戏详情全屏化与目录图文徽标

Status: ready-for-agent
Source: 2026-10-20 grill-with-docs 三轮访谈（Q1-Q10 均按推荐确认）+ to-spec 综合
Related: ADR-0001「文档模型与路由」；本次新增 ADR-0002「游戏详情从弹层改为全屏页面」

## Problem Statement

家长在手机上点开一个游戏时，得到的是一个居中弹窗：画面被压缩在遮罩层里，玩法、步骤与大图挤在一起，想看清一张步骤图还得再点一次放大。想连续看本章的下一个游戏，必须关掉弹窗、在卡片堆里找到刚才的位置、再点下一个——翻三五个游戏就要重复三轮。另外，游戏章卡片上有两个可点区域（图片弹大图、文字弹详情），点了图片只会看到一张孤零零的图，点了文字才有玩法，点击结果不可预期。最后，目录页 28 行长得几乎一样，家长无法一眼分辨哪些章点进去是"带步骤图的图鉴"、哪些是"要读的长文"。

## Solution

游戏详情从弹层改为**全屏页面**：点卡片任意位置直接进入，页面顶部是「返回列表 + 游戏名 + 第N章 · 03/10」，正文完整保留 8 个模块与四张步骤图，底部是「上一个 / 下一个」——家长可以像翻书一样在章内连续看游戏，返回时列表停在离开前的位置。卡片合并为单一入口，图片大图只在详情页内查看（能力不变：缩放、平移、四图切换）。目录行尾新增两色徽标：游戏章「图文」、文字章与附录「纯文字」，扫一眼即可区分。

## User Stories

1. 作为家长，我希望点击游戏卡片的任意位置（图片或文字）都进入该游戏的全屏详情页，以便不用瞄准小按钮。
2. 作为家长，我希望游戏详情占满整个屏幕，以便看清玩法、步骤与大图而不被压在遮罩弹窗里。
3. 作为家长，我希望详情页顶部有「返回列表」按钮，以便一键回到游戏卡片。
4. 作为家长，我希望详情页显示游戏名与所属章节，以便知道自己在看什么。
5. 作为家长，我希望详情页头部显示「第5章 · 03/10」，以便知道这是本章第几个游戏、还剩多少。
6. 作为家长，我希望详情页完整保留玩法、步骤、观察、升级玩法、安全提示等全部模块，以便换形态不缩水。
7. 作为家长，我希望详情页里看到四张步骤图，以便照着画面陪孩子玩。
8. 作为家长，我希望详情页底部有「上一个 / 下一个」按钮，以便不返回列表就能连续看游戏。
9. 作为家长，我希望到本章第一个游戏时「上一个」禁用、最后一个游戏时「下一个」禁用，以便知道是边界而不是页面坏了。
10. 作为家长，我希望桌面端用左右方向键切换上一个/下一个游戏，以便手不离键盘连续浏览。
11. 作为家长，我希望从详情返回列表后页面停在我离开时的位置，以便不用重新滚动寻找。
12. 作为家长，我希望返回后焦点回到刚才点击的卡片，以便读屏与键盘用户不迷路。
13. 作为家长，我希望按 Esc 也能从详情页返回列表，以便键盘快速退出。
14. 作为家长，我希望浏览器后退键一次就回到列表，以便符合我对网页的固有预期——即使我刚翻了 5 个游戏。
15. 作为家长，我希望在详情页点步骤图可以放大查看，以便看清画面细节。
16. 作为家长，我希望放大后能缩放、拖拽平移、左右切换四张图，以便逐张细看。
17. 作为家长，我希望放大时按 Esc 只关闭大图、详情页保留，以便继续看玩法。
18. 作为家长，我希望大图关闭后焦点回到刚才点击的图片，以便键盘用户不迷路。
19. 作为家长，我希望游戏章列表页的卡片图片不再单独弹出大图，以便点击行为可预期——点了就是进详情。
20. 作为家长，我希望目录里游戏章显示「图文」徽标，以便一眼知道点进去有步骤图。
21. 作为家长，我希望目录里文字章、前置与附录显示「纯文字」徽标，以便知道是长文阅读而不是图鉴。
22. 作为家长，我希望两种徽标颜色不同，以便扫一眼就能区分，不用逐行读字。
23. 作为家长，我希望目录行的月龄、游戏数等文案保持原样，以便徽标是增量信息而不是替换。
24. 作为家长，我希望搜索游戏名直达该游戏的全屏详情页，以便老习惯不变。
25. 作为家长，我希望搜索结果的类型标签（游戏/章节/附录/前置）保持现状，以便不因新徽标产生歧义。
26. 作为家长，我希望把游戏详情的链接分享给家人，对方打开就是同一个游戏，以便远程同步玩法。
27. 作为家长，我希望旧版本分享的游戏深链刷新后仍然直达详情，以便升级不破坏已发出的链接。
28. 作为家长，我希望深链直达详情页时点「返回列表」能正常回到该章卡片网格，以便深链用户也有完整导航。
29. 作为手机家长，我希望详情页在 360px 下无横向滚动，以便单手舒服阅读。
30. 作为手机家长，我希望详情页底部的上/下一个按钮够大易按，以便拇指操作。
31. 作为使用读屏的家长，我希望详情页是真实页面（标题与地标语义完整），以便读屏报出「第5章 黑白卡追视」而不是一个对话框。
32. 作为使用读屏的家长，我希望徽标信息出现在目录行的可访问名称里，以便不依赖视觉也知道章节类型。
33. 作为键盘用户，我希望焦点环与 Tab 顺序在详情页保持自然流动，以便不用鼠标完成全部操作。
34. 作为家长，我希望文字章、前置与附录的浏览体验完全不变，以便这次改动不影响非游戏内容。
35. 作为家长，我希望进入详情不再有遮罩与居中卡片，以便感觉这是"一页"而不是"一个框"。
36. 作为家长，我希望断网时进入详情有与现有文档一致的错误与重试体验，以便异常行为统一。
37. 作为开发者，我希望详情视图由既有路由的 gameId 派生而不新增路由类型，以便路由层零改动、深链天然兼容。
38. 作为开发者，我希望列表与详情共用同一个页面实例与同一份文档数据，以便切换零请求、返回零闪烁。
39. 作为开发者，我希望"当前游戏、章内序号、上/下一个游戏"由纯函数选择器派生，以便单测覆盖边界。
40. 作为开发者，我希望测试沿用既有缝隙（端到端冒烟 + 领域纯函数），以便不新增测试框架与维护面。
41. 作为开发者，我希望运行期体积预算显式更新而非悄悄超限，以便性能回退在门禁暴露。
42. 作为开发者，我希望架构文档、词汇表与 ADR 同步本次决策，以便文档不漂移。

## Implementation Decisions

### 1. 范围与影响面

- 仅游戏详情的形态变化；文字章、前置、附录的渲染与导航不变，目录页除徽标外不变。
- 数据契约零改动：目录、章节、文档 JSON 与图片资产原样；130 个游戏的 8 模块字段不动。
- 被推翻的既有决策：D5（详情用 `<dialog>`，理由与代价记入新增的 ADR-0002）。受影响改写：D8 的弹层焦点条款、D12 的 Esc 关弹层条款。D10（目录不显示配图）保持——徽标是文字级标记，不引入图片请求。
- 路由表不变：`#/ch/{n}/game/{id}` 继续表示"游戏章内的游戏详情"，只是渲染结果从弹层变为全屏页面。

### 2. 游戏详情页结构

- 头部：返回按钮「返回列表」+ 游戏名（页面 h1）+ 位置行「第N章 · {序}/{总数}」。位置行取章内 1 起的序号，与底部导航的进度感呼应。
- 头部**不**带「上一章/下一章」工具栏：详情是章内子页面，跨章导航归游戏章列表页。
- 正文：沿用弹层版的 8 模块排版与四张步骤图，仅容器从对话框换成文档流全屏。
- 底部：导航条「← 上一个 / 下一个 →」，按章内游戏顺序，首尾禁用；按钮面积按移动端拇指尺寸设计。

### 3. 游戏间导航与键盘

- 上一个/下一个仅限章内，不跨章；到边界时按钮禁用并保留可读状态。
- 键盘映射：无弹窗时 `←/→` 切上一个/下一个游戏，`Esc` 返回列表；方向键与底部按钮同源。
- 大图查看器打开时按键归大图：`←/→` 切图、`Esc` 只关大图、详情页状态保留。
- 焦点在输入框等表单控件内时不拦截方向键（沿用现有守卫）。

### 4. 历史与路由语义

- 列表 → 详情：`push`（浏览器后退可回列表）。
- 详情内切游戏：`replace`——后退键一次回到列表，不逐游戏入栈；翻看历史靠页面内导航。
- 返回按钮 = 浏览器后退；深链直接进入（历史栈里没有列表）时，返回按钮导航到该章列表页。
- 非法 gameId 沿用现状：回该章并提示；刷新深链仍直达详情。

### 5. 滚动与焦点

- 进入详情：记录列表视图的滚动位置与触发卡片。
- 返回列表：恢复滚动位置；焦点回触发卡片；深链进入（无触发卡片）时焦点落网格标题。
- 进入详情时焦点落详情页标题；`document.title` 随视图切换（详情态含游戏名）。
- 弹层时代的"关闭后焦点回卡片"纪律平移为"返回后焦点回卡片"。

### 6. 双视图实现

- 文档页外壳持有「列表视图 ⇄ 详情视图」两个状态，页面 key 仍为 `doc:{docId}`；不新增页面类型、不销毁重建。
- 详情视图数据由选择器从路由 gameId 派生：当前游戏、章内序号、上一个/下一个 id、首尾边界；选择器保持纯函数。
- 视图切换零网络请求、零骨架屏；游戏章正文 DOM 保留（隐藏而非销毁），滚动位置因此可精确恢复。
- 弹层生命周期（对话框开关、遮罩、焦点陷阱）整体移除；大图查看器保留，归属详情页。

### 7. 游戏卡片

- 卡片合并为单一入口：图片区与文字区都触发"进入详情"；移除图片放大按钮与「查看大图」提示。
- 可访问名称改为「查看《游戏名》玩法详情」及既有 meta 描述。
- 图片加载失败的色块兜底保留；失败时整卡仍可进入详情。

### 8. 大图查看器

- 能力不变：滚轮/双指缩放、拖拽平移、四图切换、`+/-/0` 快捷键、Esc 层级、关闭后焦点回触发元素。
- 入口仅详情页内的图片（主图与步骤图）；从详情页打开大图时只关大图、详情保留（与原弹层叠加行为一致）。

### 9. 目录徽标

- 目录行尾（箭头前）加视觉徽标：游戏章「图文」、文字章与附录「纯文字」；徽标按文档 kind 派生，两色区分，颜色取自设计令牌。
- 目录行 meta 文案不变；徽标对读屏冗余处理——视觉徽标可隐藏，信息并入行可访问名称。
- 搜索结果维持既有类型标签，不叠加图标志：所有游戏都有图，再标"图文"没有区分意义。

### 10. 可访问性

- 详情页是真实文档流页面：完整地标结构、单一 h1、Tab 自然流动、焦点环不移除。
- 键盘全功能：Tab / 方向键 / Esc（见第 3、5 节）。
- 对比度 ≥ 4.5:1；`prefers-reduced-motion` 下关闭过渡（沿用现有纪律）。

### 11. 性能与预算

- 无新增请求：详情与列表共用同一份文档 JSON；图片加载策略沿用（卡片 lazy，大图查看器非 lazy）。
- 运行期 JS：弹层代码移除、详情视图新增，净变化在预算唯一来源中显式更新，超限必须在门禁可见。
- 视图切换零网络、零骨架；缓存命中切页 < 50ms 的既有预算不变。

### 12. 文档与验收

- 新增 ADR-0002：记录放弃弹层的权衡（家长操作路径、整卡单入口、图片入口合并、后退语义更清晰）与代价（滚动/焦点从"免费"变为显式管理）。
- 词汇表已收录「游戏详情页」；本次不再新增术语。
- 架构文档更新到 v0.4：路由表、生命周期、键盘表、组件矩阵、决策表（D5/D8/D10/D12 条款）与手动验收清单。
- 端到端冒烟脚本中弹层相关用例全部改写为详情页用例。

## Testing Decisions

好的测试只验证外部可观察行为：给定输入，断言 URL、可见内容、焦点落点、滚动位置、按键结果与请求次数；不 mock 私有函数、不绑定组件内部结构、不测 CSS 细节。

**不新增测试缝隙**，沿用两处既有缝隙：

1. **端到端缝隙（最高，承担主要覆盖）**：headless Chrome 冒烟（先例：现有目录/搜索/翻页/深链/大图用例）。新增/改写用例：
   - 目录 → 点卡片 → 全屏详情（页面上不存在对话框）→ 返回 → 列表滚动位置与触发卡片焦点恢复。
   - 详情内「下一个」逐个推进到末尾禁用、「上一个」回到开头禁用；`←/→` 同步；`Esc` 返回。
   - 大图打开时 `←/→` 切图、`Esc` 只关大图且详情保留；关闭后焦点回图片。
   - 深链 `#/ch/{n}/game/{id}` 刷新直达详情；浏览器后退一次回列表；深链进入后「返回列表」可达该章网格。
   - 目录行「图文 / 纯文字」徽标按 kind 正确出现；360/768/1440 三档无横向滚动。
2. **领域纯函数缝隙**：详情视图派生（当前游戏、章内序号、上/下一个 id、首尾边界、未知 gameId 归一）与目录徽标文案派生。先例：现有路由、相邻页、搜索与选择器测试。

数据管线与仓储缝隙本次不涉及；不引入 DOM 单元测试框架。人工验收清单（架构文档）补充：连续浏览 5 个游戏后后退一次回列表且滚动位置正确、徽标在读屏下的可访问名称正确。

## Out of Scope

- 目录行缩略图（保持"目录不显示配图"决策，仅文字徽标）。
- 搜索结果叠加图标志。
- 详情页内跨章的上一个/下一个游戏。
- 详情页头部恢复上一章/下一章工具栏。
- 130 条图注并入游戏详情（既有候选，另行决策）。
- 收藏、浏览历史、最近浏览。
- 文字章、前置、附录新增任何配图。
- 新路由类型、History API 路由、小节深链。
- 打印排版、PDF 导出、离线/PWA、Service Worker。
- 多语言、深色模式、主题切换。
- 卡片视觉重设计（本次只合并入口，不改卡片风格）。

## Further Notes

- 事实基线（2026-10-20 核验）：14 个游戏章、130 个游戏全部有图（0 缺图）；14 个文字章全部无图。因此"有图/无图"的区分恒等于"游戏章/文字章"，徽标按 kind 派生即可；若未来出现无图游戏章或带图文字章，需重审徽标语义。
- 历史包袱：弹层方案曾以"保留滚动位置"为核心卖点；全屏化后该收益由显式的滚动记录/恢复承担，这是 ADR-0002 必须写清的代价。
- 实现顺序建议：先做选择器派生与领域单测（纯函数）→ 双视图骨架、返回/滚动/焦点 → 卡片单入口与目录徽标 → 键盘与深链语义 → 冒烟改写与架构文档 v0.4 → ADR-0002 收尾。每步保持应用可运行。
- 完成定义：两条测试缝隙全绿、`npm run verify` 全绿、人工验收清单全过、架构文档更新到 v0.4、ADR-0002 入库、GLOSSARY 含「游戏详情页」。

## Comments

### 2026-10-20 实现完成

- 领域缝隙：`selectDocView` 派生 `gameIndex`/`gameCount`/`prevGame`/`nextGame`；`tocBadge` 派生目录徽标（17 个领域用例全绿）。
- 冒烟缝隙：90 项全过，新增深链详情、滚动/焦点恢复、游戏间导航、Esc/方向键分层、replace 后退语义与目录徽标用例。
- 实现中发现并修正的额外事实：页面 CSS `scroll-behavior: smooth` 会让 `behavior:'auto'` 的滚动变成动画——滚动管理一律 `instant` + `history.scrollRestoration = 'manual'`；焦点回卡片必须 `preventScroll`，否则会覆盖恢复的滚动位置。
- 运行期 JS 预算 72 KB → 76 KB（净增 3.2 KB，预算唯一来源显式更新）。
- `npm run verify` 中 `check-prompts` 的 20 个图片指纹错误为工作区预存的 `panel-prompt-alignment` 工作，与本 spec 无关。
