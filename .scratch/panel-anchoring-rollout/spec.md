# 锚定落地的重画铺开

**Status:** ready-for-agent
**Slug:** panel-anchoring-rollout
**Owner:** babyGame（内容资产侧）

来源：2026-10-21 三口径一致性体检会话（触发：116 呼吸小熊组）。前置产物已落盘：GLOSSARY 三口径词条、release.md 四格一致性人工清单、理由码 A7-style（`tools/panel-ledger.mjs` 与 panel-prompt-alignment spec 已同步）、ADR-0005、抽检报告 `reports/consistency-sample-audit-2026-10-21.md`、ticket 134（research，resolved）。

## Problem Statement

读者打开游戏详情页，四张步骤图该演示同一个游戏的四步：同一种画风、同一对人物、画的是提示词说的事。

现在的状况是：未处理章节的存量图里，**每两张就有一张与提示词有明确出入**（抽检 24/44），外推全书约 280-300 张需要重画。而更麻烦的是，单纯逐格重画治不了第二类病——人物漂移：同一句人物层文本，四次独立生成会得到袖长不同、发色黑棕不定、玩偶各异的四个人。116 组甚至一张画成孕妇、一张把 24-36 月幼儿画成 3-6 月婴儿。重画规模这么大，没有锚定手段，重画完的「新图」自己就会花掉。

另外两处流程缺口：画风跑偏在理由码里没有名字（只能寄在月龄码下，统计失真）；带安全问题的图（剪刀尖朝上）和普通场景错图排在同一条按章推进的队伍里，优先级没有差别。

## Solution

在既有批次流程（panel-prompt-alignment）之上落三件事，把 ADR-0005 的锚定策略变成批次执行的标准动作：

1. **锚定生成**：重画时每格附参考图（同组 pass 格 > 同章最近校准通过图 > 最新校准图），锚人物与画风不锚构图；台账盲审记录注明参考图 key。
2. **优先批次**：插队处理一个 10 张的小批——079 剪刀初体验 ×4（含安全项）、103 浴巾躲猫猫 ×3（含禁画项）、116 呼吸小熊 ×3（已预审，ticket 118）。
3. **三口径验收**：后续每章批次按 GLOSSARY 三口径整组并排验收，画风不符记 A7-style。

完成后：读者看到的每组四张是同一家人、同一种画法、画的是当步该做的事；维护者能从台账回答「这张图的人物锚的是哪张图」。

## User Stories

1. 作为**读者**，我希望同一游戏四张图里的妈妈穿着、发型一致，这样我不会以为是两个家庭。
2. 作为**读者**，我希望四张图里的宝宝月龄感一致且与标注月龄相符，这样我不会对孩子能力产生错误期待。
3. 作为**读者**，我希望图里画的就是该步的动作，这样照着图做不会做反。
4. 作为**读者**，我希望图里不出现剪刀尖端朝人、画面内文字这类问题，这样我不会照着做错或被干扰。
5. 作为**家长**，我希望道具玩偶在四张图里是同一只，这样孩子认得出「自己的熊」。
6. 作为**编辑**，我希望画风跑偏有自己的理由码（A7-style），这样缺陷统计不再失真。
7. 作为**编辑**，我希望每章批次按画风/人物/内容三口径整组验收，这样「一张对三张错」的组不会漏网。
8. 作为**美术**，我希望重画时自动附带参考图锚定，这样不用每格凭文字赌人物长相。
9. 作为**美术**，我希望参考图只锚人物画风、不锚构图，这样动作和镜头仍由提示词说了算。
10. 作为**审核者**，我希望台账记录每格用的参考图 key，这样「这张图的人物像谁」可追溯。
11. 作为**审核者**，我希望盲审把「被参考图带偏的动作/场景」列为例行检查项，这样锚定不引入新偏差。
12. 作为**维护者**，我希望锚定策略不改任何校验接缝，这样 `npm run check` 的清单校验继续直接可用。
13. 作为**维护者**，我希望安全项、禁画项格子优先于普通场景错图重画，这样风险敞口最先关闭。
14. 作为**维护者**，我希望批次可以中断续跑、失败重试上限不变，这样 280 张的规模不会一次压垮。
15. 作为**发布者**，我希望重画成果双仓回写（babyGame panel_web + 书稿仓），这样 `npm run data` 不会用旧图覆盖。
16. 作为**新接手的人**，我希望 ADR-0005 讲清为什么选参考图而不是种子，这样我不会重新发明一遍锚定方案。

## Implementation Decisions

- **接缝（唯一）**：沿用 `npm run check` 内的清单校验（panel-prompt-alignment spec 已定的校验接缝）+ 人工盲审。不新增命令链、不新增校验入口。锚定不改变清单 schema——参考图 key 记在盲审记录，不进台账列，避免 schema 变更波及已完成的 ch05-ch07 台账。
- **优先批次只动提示词**（2026-10-21 修订）：079、103、116 三票不产图，交付「按正文补强的提示词 + 每格参考图 key + 出图任务单」。理由：提示词按正文内容调整，不回头迁就旧图；出图与盲审留给后续出图批次。
- **台账按游戏增量落账**（2026-10-21 修订）：逐游戏铺开与跨章插队要求「一章只落部分格子」合法；未落账的格子只进覆盖统计，重复 key、指纹过期、备份缺失等硬失败仍从严。这是对既有「每个 key 恰好一行」的一处放宽，须同步 panel-prompt-alignment spec 的校验接缝段。
- **共享层只加否决型约束**（2026-10-21 修订）：按正文补人物层体型约束、负面层剪刀朝向安全项、负面层「提示词外道具」禁令三处，只写禁什么、不加正向新要求。共享层一动全书提示词 hash 全变，既有台账做机械重基线（只改 prompt_hash，不重看旧图），判据写进批次记录。
- **锚定选图顺序**（ADR-0005）：同组 pass 格 → 同章最近校准通过图 → 最新校准通过图。参考图与提示词冲突时提示词优先（权威顺序 ADR-0003）。
- **生成顺序**：整组四格先出一张锚定基准（首个 pass），再锚它生成其余三张；与「整组判定、整组生成、整组验收」的既有单位一致。
- **A7-style 已生效**：`tools/panel-ledger.mjs` 的 `REGEN_REASONS`、panel-prompt-alignment spec 的 reason 枚举、GLOSSARY、release.md 均已同步；存量寄在 A4 的画风判例（ticket 118 的 116-2）已改记 A7-style。
- **优先批次构成**：079-1~4（A2×1、A3×3、含 A5 安全）、103-2/3/4（A3、A6、A1）、116-2/3/4（A7+A4、A1+A3、A3+人物），共 10 张，恰在单批上限内。116 的逐格判定已预填 ticket 118。
- **批次纪律不变**：串行生成、指纹备份、无备份不覆盖、≤2 次重试转 needs-human、双仓回写（ADR-0004）。
- **验收口径**：每组并排按三口径过 release.md 的人工清单；画风不符记 A7-style。

## Testing Decisions

- 好的测试只验证外部行为：给一份台账和一组图片，能否判定「这批可发布」。
- **清单校验扩展用例**：A7-style 作为合法 regen 理由的正用例；ch05-ch07 旧台账（无 A7 行）回归不破坏的负用例。先例：`panel-ledger.mjs` 现有的 decision/reason 枚举正反用例。
- **增量落账用例**：一章只落部分格子的台账通过校验，覆盖统计如实；同章内重复 key、指纹过期、备份缺失等仍逐类报错。先例：现有七类失败用例改成「部分章」前提后必须仍全中。
- **盲审（人工）**：只对改过的图做第二轮盲审，看图与提示词，例行检查「被参考图带偏的动作/场景」；结论与清单不一致转 needs-human。
- **不做自动化**：画面像不像、人物像不像参考图——只能人眼 + 理由码，分歧即升级。

## Out of Scope

- 修改共享层除三处否决型约束（人物层体型、负面层剪刀朝向、负面层提示词外道具）以外的文本；A7 只是判定码，不为 A7 改提示词内容。（2026-10-21 修订）
- 修改章节正文、图注、插画脚本、数据抽取。
- ch05-ch07 已 verified 台账的追溯改码（历史上没有 A7，不回填）。
- 一次性整批重做 520 张：仍按章分批、按需重画。
- 为审美升级重画；种子控制（通道不可用，留待通道支持时修订 ADR-0005）。
