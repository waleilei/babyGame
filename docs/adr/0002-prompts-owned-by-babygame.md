# 提示词目录归 babyGame 所有

Status: accepted

520 条提示词此前只存在于书稿项目的 `prompts/image-prompt-catalog.md`，而图片、图片编号与「游戏 → 四张步骤图」的对应关系只存在于 babyGame。我们决定把这份目录复制进 babyGame 并成为唯一来源，书稿项目不再保留；理由是两份拷贝一旦分叉，图片编号与提示词会失去可验证的对应，而这种漂移在 520 条的规模下无法靠人工发现。

## Considered Options

- **书稿项目保留唯一来源，babyGame 用脚本导入**：单一来源最干净，但导入脚本必须跨工作区读文件，门禁就依赖一个不在仓库里的路径；且书稿项目明确不再维护这份目录后，导入脚本会指向一个空壳。
- **运行期读取书稿项目的 markdown 并解析**：跨仓库请求，且把 20 万字节的解析搬进浏览器，与「构建期解析、运行期零依赖」的纪律相反。

## Consequences

- 迁入不是搬运而是重写：449 条旧文案要按四层模板重写，520 张归档图与文案的对应关系会被有意放宽。原总表因此冻结进 `prompts/archive/` 作为唯一溯源，并产出一次性差异报告，之后不再改动。
- 文案从「一张图一段话」变成「共享层 + 格层」的组合结果，改一处风格或场景词会波及整批图；这提高了复用，也意味着共享层的改动必须整批复核。
- babyGame 从此承担这项内容的维护职责，需要在 `AGENTS.md` 与架构文档里写明入口。
- 书稿项目的生成流水线若仍要读提示词，改为消费 babyGame 的产物。
