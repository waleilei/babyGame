# 文档模型与路由：统一“文档”，保留 `#/ch/{n}`

Status: accepted

网页从“14 个游戏章”扩为全书后，出现了没有章号的前置与附录。我们决定在数据层引入统一的“文档”列表作为唯一有序来源（`front`、`ch01`…`ch21`、`apx-a`…`apx-f`），目录分组只引用文档 id；路由层保留 `#/ch/{n}` 以兼容已有游戏深链，并为无章号文档新增 `#/front` 与 `#/appendix/{a-f}`；渲染层按 `kind` 分成游戏章页与文字章页，而不是把长文塞进现有章节组件。

## Considered Options

- **统一 `#/doc/{id}`**：模型最干净，但会让已经分享出去的 `#/ch/5/game/01` 全部失效，收益不足以抵消迁移成本。
- **前置拆 3 页、附录合并 1 页**：前置只有约 1,200 字，拆页反而增加导航；附录合计约 6,600 字、13 张表，合并后单页过长，移动端难以定位。
- **把文字章塞进现有章节页**：会迫使游戏页承担弹层、大图、卡片网格与长文两套生命周期，增加回归风险。

## Consequences

- 目录数据版本升到 2，文档数据版本同步升到 2；仓储只接受新版本。
- 文字章需要一套块契约与渲染器，运行期 JS 预算相应上调。
- 章节页只做“文档 id 化”的最小改动，游戏体验保持不变。
- `captions.md` 不进入文档模型；它是 130 条游戏图注，按 id 并入游戏详情是另一项决策。
