# 游戏详情：从弹层改为全屏页面

Status: accepted

游戏详情原本是原生 `<dialog>` 弹层（深链 `#/ch/{n}/game/{id}` 打开弹层）。v0.4 把它改为同一文档页内的全屏视图：点卡片任意位置直接进入，头部是「返回列表 + 游戏名 + 章内位置」，底部提供上/下一个游戏；步骤图大图只在详情页内打开。此决策推翻 v0.3 决策 D5（详情用 `<dialog>`）。

## Considered Options

- **保留弹层**：滚动位置与列表上下文“免费”保留；但家长连续看多个游戏要“关弹层—找卡片—再点”三轮操作，卡片上图片（弹大图）与文字（弹详情）两个入口让点击结果不可预期，弹窗内再看大图是叠层弹窗。
- **独立详情页（新页面类型）**：职责更“正统”，但进出都要销毁/重建页面，滚动与焦点要跨页面对象传递，切换有可感知的重建开销。
- **文档页双视图（选定）**：详情是同一文档数据的第二个视图，由路由 gameId 派生，切换零请求、零重建、零闪烁；滚动与焦点改为显式契约。

## Consequences

- 弹层的焦点圈定、遮罩与关闭纪律移除；键盘由文档页按视图接管——详情内 `Esc` 返回列表、`←/→` 切上/下一个游戏，大图打开时按键归大图。
- 滚动从“浏览器免费”变为显式契约：`history.scrollRestoration` 设为 `manual`；进入详情 `instant` 回顶，返回 `instant` 恢复离开位置（页面 CSS 的 `scroll-behavior: smooth` 会让 `auto` 变成动画滚动，不能用）；焦点回触发卡片时 `preventScroll`，避免把视口从恢复的位置拽走。
- 历史语义：列表→详情 `push`；详情内切游戏 `replace`（浏览器后退一次回列表）；深链直接进入时返回按钮 `replace` 到列表。
- 卡片合并为单入口（图片与文字都进详情），大图按钮与“查看大图”提示移除；大图入口只剩详情页内的图片。
- 游戏章目录行新增「图文」徽标、文字章「纯文字」徽标（按文档 `kind` 派生）；事实基线是 130 个游戏全部有图、14 个文字章全部无图，若未来出现无图游戏章或带图文字章需重审徽标语义。
